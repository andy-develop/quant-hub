## 1. 背景与目标

三个独立策略仓各自长出了数据层、门禁、发布逻辑，重复且互不兼容：

| 原仓 | 域 | 核心内容 | 主要痛点 |
|---|---|---|---|
| `andy-develop/stock-factor-engine` | ①短线（quant-lab）+ ③个性化选股 | 动量轮动 + LightGBM 黑盒；因子选股页 | §0.4 沪市覆盖故障（生产事故中）；两套构建脚本重复 |
| `andy-develop/red-dividend-strategy` | ②ETF | 红利低波 + 行业轮动 + 沪深300 择时 | 数据格式与①不兼容 |

合并原则（方案冻结）：

1. **数据契约单一出处**：`common/store/schema.py`，`CONTRACT_VERSION = "1.0"`
2. **门禁先行**：覆盖率 <95% 黄 / <80% 红（红 = 中止不落盘）
3. **hfq 永久冻结**：历史后复权价永不改写（信号可复现）
4. **三域前端隔离共存**：不统一样式，不统一涨跌色

## 3. 数据契约（冻结项，改前必须开会）

`common/store/schema.py`：

```python
CONTRACT_VERSION = "1.0"
COLUMNS = {"code": "string[pyarrow]", "date": "date32",
           "open/high/low/close": "float64", "volume": "int64", "amount": "float64"}
OPTIONAL = {"turnover": "float64"}
PRIMARY_KEY = ("code", "date")
RETENTION = {"stock": 730, "etf": 2430, "index": None}
BROAD_INDEX_CODES = ("sh000001", "sz399001")
```

**三条硬性陷阱（违反即数据事故）**：

| # | 陷阱 | 规则 |
|---|---|---|
| T-1 | volume 单位 | 契约 = **股**；腾讯快照原始字段也是股；但成交额是**万元 → ×1e4 转元**。任何"看起来太小/太大"的量先查单位 |
| T-2 | 代码归一顺序 | **先 normalize 后 fixup**。顺序颠倒 → 覆盖 isin 全 miss → 整段重复行（2026-09-08 实际发生过） |
| T-3 | hfq 冻结 | `writer.write_incremental` 对已存在 `(code,date)` 的 hfq 行直接 raise。要重算 = 全量重导，单独评审 |

**is_partial 的正确语义**（H-1 审计结论）：不排除"抓取日还在周中间"的不完整周，会让 **97.7% 的周中日期拿到错误的周线信号**。`calendar.is_partial_period()` 的 `asof` 是**抓取日**不是周期末日，实现里 `probe_from = max(start, dd + 1day)`。

## 4. §0.4 沪市覆盖故障（已修复，含回归锁）

### 4.1 事故数字

2026-09-07 ~ 09-10 连续 4 个交易日：

| 日期 | 入库 | 沪市（在市 2316） | 深市（在市 2899） |
|---|---|---|---|
| 09-04（正常） | 5015 | 2234（99.4%） | 2781（95.9%） |
| 09-07~10 | ~2925 | **39（1.7%）** | ~2886（99.6%） |

`39 = 2316 − 38×60`：每批 60 只，前 38 批整体失败被**静默丢弃**。

### 4.2 根因（四条静默 continue）

```python
except Exception:              # ① 整批失败只 sleep(2)
if len(parts) < 40: continue   # ② 限流降级格式字段少
sym_full = ("sh" if line.startswith("v_sh") else "sz") + sym   # ③ ★
except ValueError: continue    # ④ 方案漏列的第 4 条
```

③ 是元凶：降级响应前缀是 `v_s_sh600004`，`startswith("v_sh")` 为假 → 沪市判成深市 → 不在 sym_map → 整批丢弃。深市走同一 else 分支恰好正确，所以只死沪市。

### 4.3 修复（三层）

1. **vendor 层**：`common/datasource/vendor_tencent.py` 的 `_market_of_line()` 显式解析 `v_ / v_s_ / sh|sz|bj`，市场与格式解耦；降级格式单独解析路径
2. **脚本层**：`patches/quant-lab/scripts/daily_update.patched.py` —— 批次指数退避重试 3 次 → 逐只重试 → 全部计数（`FetchStats`）→ runlog 落盘
3. **门禁层**：`common/gates/coverage.py` **分市场下限**（`per_market_floor`）——故障日整体 55.8% 会判黄放行，但沪市 1.7% 触发红灯中止

### 4.4 回归锁

`tests/incident/test_shanghai_coverage.py`（18 项）用真实响应形态复现事故，任何回退都会红：

- `test_old_binary_judgement_would_fail`：证明旧写法必错
- `test_fault_day_reproduces_1p7pct_and_blocks`：39/2886 → 必须 raise
- `test_cross_market_gate_catches_what_overall_gate_misses`：分市场下限的存在理由

## 5. 前端合并（单页壳）

### 5.1 冲突实证（为什么必须隔离）

三域模板标识符重叠实测：

- CSS 类：16 个跨域重名（`card`/`brand` 三域全撞）
- id：`sidebar` 撞（etf ∩ stock）
- JS：`esc` 函数撞

### 5.2 隔离三件套（`web/shell/scope.py`）

1. **选择器前缀**：`.card{}` → `#app-{domain} .card{}`
   踩过的坑（均有回归测试）：CSS 注释吞下一个选择器块；全局块（body/*）泄漏覆盖壳层；已前缀的再前缀产生死规则
2. **涨跌色逐域冻结**（★ 不可"统一"）：

| 域 | `--up` | `--down` | 惯例 |
|---|---|---|---|
| 短线 | `#D5423E` 红 | `#1D9E75` 绿 | 中国 |
| ETF | `#E0443C` 红 | `#16A34A` 绿 | 中国 |
| **个性化选股** | **`#16A34A` 绿** | **`#DC2626` 红** | **美股（颠倒）** |

   `test_stock_domain_is_actually_inverted` 防止好心人把它们统一掉。
3. **id 命名空间**：`id="sidebar"` → `id="etf__sidebar"`，JS `getElementById` 同步改（注意先改 JS 再改 id，防止双重前缀）

### 5.3 构建

```bash
python -m web.build --src <三仓检出目录> --out web/dist/index.html \
    [--payload-dir state/payload]
```

- ECharts 内联（CDN 与 `document.write` 兜底 loader 全部清除，发布页零外网依赖）
- 产物 ~1.2 MB 单文件，可离线打开
- 无 payload 时保留占位符显示空态，不崩
